# 首页是怎么做出来的（过程 + 原理 + 最终效果）

> 范围：`uniapp/pages/home/home.vue`（首页焦点形态）及其配套改动
> 时间线：2026-10-16 ~ 2026-10-17，共 6 次迭代（第六版 → 第十一版）
> 一句话版本：**把首页做成一张和屏幕一样大、完全透明的卡；往上一滑，是"这一整张卡"在往上走并被糊掉，下面那摞模块卡像一张毛玻璃抽屉从下面被丢上来。**

---

## 一、先看成品：现在滑一次手指会发生什么

把整个过程按手指的位置切成四段：

| 阶段 | 屏幕上半部（主页 hero） | 屏幕下半部（模块抽屉） | 手上感觉 |
|---|---|---|---|
| **静止（在最顶）** | 背景图**高清**，中间两个大按钮「背句子 / 背单词」+ 一行关键信息 + 一行小字（复习错题 / AI 薄弱点专练）。按钮落在**屏幕正中** | 模块卡在折叠线之下，看不见 | 无 |
| **起手（前 16rpx）** | 完全没变化 | 完全没变化 | 无（这是故意的死区，防手抖先闪一下） |
| **滑动中** | 整张主页**整体上抬 56rpx**、同时缩到 **0.95**（像往后退)；上面的字**先一步淡出**（×1.2 提前到位);背景开始按五档**长出模糊**——看得出主页在"失焦退场" | 一整块毛玻璃底板 + 卡片**落后于滚动 220rpx**地往上被拉上来，同时从 0.955 放大到 1，**透明度跟着 0→1** | 跟手、连贯，两层之间有明显速度差（视差） |
| **拉到位（≈滑满 520rpx）** | 主页已经糊成一片、内容淡到几乎不见，且不再吃点击 | 卡片完全实体化，压在 blurred 的主页之上 | **震一下**（比导航点击稍重），抽屉**轻轻 Q 弹**一下：先冲过头 -16rpx 放大 1.026，再回落 +5rpx 缩到 0.995，二段 -2rpx，最后归位，全程 340ms |
| **滑回顶部** | 模糊归零，**背景重新变回高清原图** | 卡片透明度回去、沉回折叠线之下 | 滑回去再拉才会再震一次（一次来回只响一声） |

关键的用户体验约定（也是你逐条提过、最后落成的四条）：

1. **动起来才有模糊，静止必须是高清背景图。** 模糊只存在于"滑到下面那屏"的过渡里。
2. **整体感，不是只有下面那摞卡在动。** 上滑时是整张主页在退（上抬 + 缩小 + 变糊），所以有景深。
3. **对比度要够。** 下面那层抽屉底板是"有实体感"的玻璃（本体色 + 渐变 + 高光描边 + 双层投影 + 20px 模糊），跟上面那张透明卡形成对比，而不是两块都若隐若现。
4. **震动有三档、可调、可关**，分别在：底部菜单点击、抽屉拉到位、设置页「试一下」。

## 二、过程：每一句话是怎么被解决的

### 第 1 轮：「上滑没动画、按钮不渐隐、抽屉不明显，最好加动效，或者加个震动；点底栏也震；设置里能调。」

**现象**：代码写了，脚本全绿，真机**一点效果都没有**。

**根因（这轮最大的坑）**：uni-app 的 App 端，**逻辑层没有 `document`**。上一版的实现是 `ref` 拿到节点后 `el.style.setProperty('--reveal', p)`，还加了"先验有这个方法再写"的兜底 —— 结果真机上那个"验"每一次都不通过，整条链路**静默失效**。既没有报错，也没有动画。

**改法**：

- 进度不再写 DOM，改成**响应式数据**（`revealP` / `revealOn`），由 computed 变成 `:style` 内联下发 —— 这是 App 端**唯一**能用得通的样式通道。
- 内联样式 **只认 px**，uni-app 不会转换内联里的 rpx → 自己写 `upx()` 做 `uni.upx2px` 换算。
- 内联里同时写**真实属性**（`opacity` / `transform`），不只写 CSS 变量 —— 真实属性一定生效，CSS 变量只是保底。
- 进度 **量化到 0.05 一档**：一次最多 20 次赋值，而不是每帧一次。home.vue 模板很大，按帧写 = 整页按帧重渲染 = 掉帧。5% 的透明度跳变肉眼看不见。
- 顺手修了一个真机报错：`syncReveal` 被放到了 `methods` 之外（跟生命周期选项平级）→ 报 `this.syncReveal is not a function`。

**触感**：新增 `uniapp/utils/haptic.js`，接在底栏 `go()`（场景 `tap`）和抽屉拉到位（场景 `drawer`）；设置页新增「触感反馈」分组（开关 + 轻/中/强 + 试一下）。
> ⚠️ Android 需要 `android.permission.VIBRATE`，已在 `manifest.json` 声明。**权限是安装时权限、但改 manifest 必须重新打包 / 重打基座** —— 老基座里没这个权限，真机调试会静默失败。这条下面还会提。

---

### 第 2 轮：「玻璃效果感觉缺了立体感，不像苹果那种。」

**查阅到的规则（也是后面反复用到的那棵树）**：CSS 里 **backdrop root** 由 `opacity<1` / `filter` / `mask` / `mix-blend-mode` / `will-change(这些)` / `isolation` 这些属性创建。某一层一旦成了 backdrop root，它子级所有 `backdrop-filter` 就只能糊到**这一层内部**的东西。

当时的结构是：毛玻璃底板挂在 `.mod-list::before` 上，而 `.mod-list` 正是那个要靠 `opacity` 淡入的层。**一淡入就自带 `opacity<1` → 底板的 backdrop 被隔离在这一层里 → 背后只有卡片自己，糊了个寂寞。** 你看到的自然就是"一块平涂半透明白片"。

**改法**：把底板从"要淡入的那层"里搬出来，另起一层：

```
.mod-sheet      ← 宿主：只吃 transform（transform 只建 stacking context，不建 backdrop root）
  ::before      ← 玻璃底板本体（不透明度、渐变、模糊、投影）
  .mod-list     ← 只有它淡入（opacity），底板不再受牵连
```

同时给玻璃加"立体感四件套"：

- **顶沿内高光** `inset 0 1.5rpx 0 rgba(255,255,255,.6)` —— 玻璃上沿接光的那道亮线，立体感最明显的一条
- **底沿内暗边** `inset 0 -1.5rpx 0 rgba(shadow,.08)` —— 给一点厚度
- **整圈 hairline 内描边** `inset 0 0 0 1rpx rgba(255,255,255,.32)` —— 比 border 更贴圆角，还不占位
- **双层外投影** 近层紧贴（10rpx）+ 远层扩散（48rpx）—— 真的"浮"起来

另外加了**表面渐变**：顶部一团径向环境反光 + 自上而下"亮 → 透 → 底部压暗"。平涂半透明看着就是灰片，有明暗过渡才是一块有厚度、有朝向的玻璃。

> 还有一条必不可少的例外：App.vue 的 `.bg-flat` 会用 `!important` 关掉**所有** `backdrop-filter`（理由是背景是平滑渐变时糊了看不出差别、白付逐帧成本）。抽屉底板是唯一的反例 —— 它背后不是背景，是**首页内容**。所以这条要用同等级别的 `!important` 抢回来。

---

### 第 3 轮：「Q 弹一点，像卡片从远处丢过来；幅度别太大。另外卡片底部背景太白了，根本不是玻璃。」

**Q 弹**：`@keyframes sheet-pop` 挂在专门的 `.mod-throw` 层上。

为什么另起一层？`.mod-sheet` 身上有一条**正在跟手走**的内联 `transform`。CSS 动画的优先级高于内联样式 —— 动画一上脸就会把跟手的位移**冲掉**。挂在父层，两条 transform 靠父子相乘，互不打扰。

曲线（幅度刻意压得很小，大了就成了弹窗，廉价）：

```
0%    → Y 0      scale 1
26%   → Y -16rpx scale 1.026   （冲过头）
54%   → Y +5rpx  scale 0.995   （回落压一点点）
78%   → Y -2rpx  scale 1.003   （二段余震）
100%  → Y 0      scale 1
```
340ms，`cubic-bezier(.22,.61,.36,1)`。

**踩到的第二个动画坑**：第一次拉上去会弹，第二次就不弹了。原因是同一个 class 摘下再戴上，Vue 会在**同一次渲染里合并掉** → 动画根本没重新播。解决办法是 `pop-a` / `pop-b` **两份内容完全一样的 keyframes**，用计数器 `popSeq` 交替挂。

**去奶白**：这里改的是**页面底部的屠屏抽屉底板** —— 本体色从偏实的那一档往下压，形体改由高光 / 描边 / 投影 / 表面渐变撑住。（下一轮全屏透明卡上线后又把这档**调回 0.14**，见下面第 4 轮 —— 因为上面那张卡变成全透明之后，底板成了下面那摞卡唯一的实背景，太透会让卡片和底板分不开。）

---

### 第 4 轮：「把主页做成一个和全屏一样大的卡片，滑的时候是整个首页在往上滑。」
### 第 5 轮补充：「这卡是透明的，只有滑下去的时候主页才变模糊并隐去；滑回来主页背景还是清晰的。」

这是改动最大的一轮，**把 hero 拆成了三层，每层只干一件事**：

```
.hero-card     外框：什么都不吃（无 transform / 无 opacity）—— 只给卡面提供定位基准
  ├─ .hero-glass  卡面：backdrop-filter（静止全透明，上滑时按五档长出模糊）
  └─ .focus-hero  外壳：只吃 transform（整屏上抬 + 缩小）
       └─ .hero-body  内容：只吃 opacity（关键信息 / 两个入口 / 小字）
```

为什么必须这么切？因为**外壳要负责"整屏往上抬"，而它绝不能带 opacity** —— 一旦带上，它自己就成了 backdrop root，卡面的 `backdrop-filter` 从此只能糊到它内部那点东西，**糊不到背景图**。表现就是你看到的"整张卡只是在平移，背景图纹丝不动"。所以内容的渐隐被搬到了内层 `.hero-body`，外壳这辈子不许再写 opacity（这条 MEMORY 里是第二次撞上同一棵树）。

**模糊为什么分成五档、不随进度连续变化**：卡面背后是 fixed 不动的背景层，整段滚动里"要糊的内容"其实没变 → 每档至多重算一次高斯模糊就够了。**逐帧改 blur 半径 = 整屏高斯按帧重跑**，那是早就走过的掉帧老路。所以：

| 档位 | 卡面不透明度 | 模糊 |
|---|---|---|
| 0（静止 / 非焦点 / 卡片全收纳） | 0 | none（**背景高清**） |
| 1 | 0.28 | blur(6px) saturate(140%) |
| 2 | 0.52 | blur(12px) saturate(150%) |
| 3 | 0.76 | blur(18px) saturate(165%) |
| 4（拉满） | 1 | 复用抽屉底板那一档（跟着画质设置等比缩放） |

只切 class，不过渡半径，只过渡 opacity（160ms），目的是让台阶式跳变看起来连贯。

**"卡面不能给任何 `background-color`"**：没有模糊支持时给本体色，就等于一整块奶白垫片盖住主页 —— 正是上一轮被砍掉的东西。所以老 webview / 不支持 backdrop-filter 时，这一整层直接 `opacity:0` 拿掉，宁可没有。

**同时把抽屉底板的本体色调回 0.14**：上面那张卡变成透明之后，底板成了下面那摞卡唯一的实背景。0.09 那版太透，卡片跟底板几乎分不开；回到 0.14 之后仍然能透出首页背景，但卡片压在上面看得出是一层实体。

---

### 第 6 轮：「整页模糊左右占不满屏幕。」

**根因很隐蔽**：`.hero-glass` 当时是 `.focus-hero` 的**子节点**，而外壳带着 `scale(1 → 0.95)` —— 卡面跟着一起缩，满糊时左右各空出 **2.5% 屏宽**。

**改法**：把卡面挪出外壳，挂到 `.hero-card` 上，变成外壳的**兄弟**节点，靠 `z-index: 0 / 1` 压在内容之下。这样它不再受 scale 影响，左右各外扩 28rpx（正好抵消 `.container` 的左右内边距）→ **宽度精确等于屏宽**。

> 顺带记一笔：想靠加大外扩去补偿缩放是**错的** —— 那等于把整屏高斯的面积放大三到四成，正是这一轮一直在躲的开销。

---

### 第 7 轮：「这些页面应该都是跟着屏幕变的吧，不要换部手机比例就完全变了。」

之前的实现有一个隐含假设：屏幕尺寸是恒定的。实际上有三个地方会脱节。

1. **rpx 只跟屏宽走，不跟屏高走。** hero 的纵向留白是 108rpx + (24 + 220)rpx，正常竖屏（约 1:2.1）没问题，但屏幕一"变扁"（横屏 / 折叠屏展开接近正方形），这 244rpx 换算出来能占掉屏高的六成 → 内容盒被挤成负数、入口被顶出屏幕、hero 被撑得比屏幕还高。修法是给上下留白加 **vh 上限**：`padding-top: min(108rpx, 14vh)`、`padding-bottom: min(24rpx + 220rpx + safe, 34vh)`。竖屏下 `min()` 不生效（244rpx 只占屏高约 15%），只在真的变扁时才接管。保留了不支持 `min()` 的老 webview 兜底行。
2. **px 缓存是按"当时那块屏幕"算的。** `syncReveal` 逐帧要用 `_spanPx / _parallaxPx / _heroLiftPx / _deadPx`，这些是 `uni.upx2px` 换算后缓存下来的（缓存是为了不每帧调同步原生接口）。屏宽一变它们就全都不对 → 新增 `remeasure()`，在 `created` 和 **`onResize`** 各调一次（后者紧跟 `syncReveal(-1)` 重新对齐）。折叠屏展开 / 分屏 / 横竖屏切换都会走到这里。
3. **安全区的实测值也有缓存。** `theme.js` 的 `safeInsetPx()` 缓存了 `--safe-b`，屏幕变了必须清 → 新增 `resetSafeInset()`，`theme-mixin.js` 的 `onResize` 里调用并重刷根节点样式。

换算兜底：`remeasure()` 拿不到屏宽时按 375 宽做 0.5 换算，并把失败 warn 出来（项目规矩：原生调用的 catch 不许完全静默）。

## 三、最终的参数表（便于以后调）

**进度换算**（`syncReveal`）

```
p = (scrollTop − 16rpx) / 520rpx      死区 16rpx：起手那点抖动不该让卡片先闪
p 夹到 [0,1]，再量化到 0.05 一档
非焦点模式 / 卡片被全部收纳 → p 恒等于 1（卡片常显、入口不淡出）
```

**每层一条的输出**（全部是 `opacity` / `transform`，零重排）

| 层 | 表达式 |
|---|---|
| 抽屉位置 `.mod-sheet` | `translateY((1−p) × 220rpx) scale(0.955 + 0.045p)` |
| 卡片 `.mod-list` | `opacity = p` |
| 主页外壳 `.focus-hero` | `translateY(−p × 56rpx) scale(1 − 0.05p)`，`transform-origin: 50% 42%` |
| 主页内容 `.hero-body` | `opacity = 1 − min(1, p × 1.2)`（比淡入早 20% 到位），`p` 过 0.9 时 `pointer-events: none` |
| 主页卡面 `.hero-glass` | 按 `p` 落到 0~4 档，见上面的档位表 |

**触感**：三档 轻 12ms / 中 22ms / 强 34ms；场景倍率 底栏 `tap` ×1、开关 `switch` ×0.8、抽屉到位 `drawer` ×1.15；**70ms 连点保护**（Android 上连续 `vibrate()` 会把短震叠成长震，手感全毁）；优先 `plus.device.vibrate(ms)`，退 `uni.vibrateShort`；失败信息落在 `lastError()`，设置页据此提示"多半是这个包没打进震动权限，云打包一次就有了"，而不是假装"本设备不支持"。

**抽屉玻璃底板**：本体色 `rgba(surface, 0.14)`；表面 = 顶部径向反光 0.34 + 线性从上到下 0.26 → 0.07 → 0 → 底部压暗 0.05；`blur(20px) saturate(190%)`（比卡片的 12px 糊得狠一点，大面积才吃得住，也更接近苹果的 sheet）；四件套投影；左右上下各外扩 28rpx 兜住"抽屉的边"。

**降级 / 兜底清单**（每一条都有对应选择器，别删）

| 情形 | 处理 |
|---|---|
| `.bg-flat`（背景是平滑渐变，全局关掉所有模糊） | 抽屉底板和主页卡面两条用同等级 `!important` **抢回来**（它们糊的是首页内容，不是背景） |
| `.perf-smooth`（低端机流畅模式） | 抽屉底板关模糊、抬本体色到 0.6；主页卡面**直接整层拿掉**（整屏高斯是最贵的一笔绘制）。退化成"只有内容渐隐 + 卡片上滑"，跟改版前手感一样 |
| 不支持 `backdrop-filter` 的老 webview | 同流畅模式：底板抬本体色 0.62，卡面直接消失 |
| `.fx-motion-off` / `.fx-motion-reduced` / 系统偏好 reduce | Q 弹回弹 `animation: none`（纯装饰动作必须跟着一起停） |
| JS 一环没跑（首屏、`onReady` 之前） | CSS 静态默认值必须保证"入口在、卡片看得见"。**绝不靠 CSS 把初值锁 0** —— 这条早期踩过：JS 没覆盖就永久隐藏 |

## 四、为什么不用那些更"直白"的做法

这一块是全过程中最贵的一批教训，写下来是为了别再走回头路：

- **不做自定义手势 + 高度过渡的抽屉。** 早期几版想用"把手 + max-height/min-height/padding 过渡"做真抽屉，每次都被反馈"上滑没反应"或者"掉帧"。掉帧根因是**动画了布局属性**：每帧重排首屏 + 重做整屏毛玻璃。而"往上滑看下面的卡片"本来就是页面滚动，交给合成器（opacity / transform）零重排。
- **不量节点。** `getBoundingClientRect` / 通过 ref 写样式这条路，在 App 端逻辑层没有 document 的前提下**每次都验不过**，而且失效得极其安静（不报错、脚本照绿）。进度只能来自 `onPageScroll` 报的 `scrollTop` —— 这是唯一不依赖 DOM 的滚动数据源。
- **不再合并层数。** 现在这五层结构不是过度设计，每一层都是被某一条 CSS 规则逼出来的：宿主一层（避免 backdrop 被 opacity 隔离）、动画一层（避免动画覆盖跟手的内联 transform）、内容一层（避免外壳带 opacity）。

## 五、质量保障现状
