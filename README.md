## 功能全览

### 词库

| | |
|---|---|
| **内置题库** | 640 词（入门 / 基础 / 进阶 / 冲刺 4 档 × 160）+ 626 例句 + 986 常用词 |
| **批次推进** | 20 词一批切成 32 批，**掌握 70% 才解锁下一批** |
| **自建与导入** | 新建空白词书、导入单词、**AI 按主题生成词书**（可限 1–500 词，或选「不限」持续生成到覆盖完整） |
| **查词** | 先查当前词书 → 再查内置词典 → 接了 AI 才由 AI 补充，**AI 补的词不会偷偷塞进你的词书** |
| **熟词过滤** | 抽 20 个词估一次词汇量，**认识的直接整段跳过** —— 不用从 abandon 开始假装不认识 |

### 练习

- **双向出题**：英译汉 / 汉译英随机混合，难度跟着掌握度走
- **两种作答**：选择题点选，或手动输入挨个判
- **一遍答对不算会，还得换着法子答对**：同一个词要连过 **3 关**——**认得出**（看词选中文）→ **想得起**（看中文选英文）→ **写得出**（看中文+首字母拼写）。三关的提取难度递增（识别 < 回忆 < 产出），换路径本身就是强化；三遍同一种题型考的还是那一条记忆通路
- **当场会了不算完，跨天还要巩固**：当场过三关只算"今天会了"，随即进入**跨天巩固队列** —— 1 / 3 / 7 / 15 / 30 / 60 / 100 天逐次拉长地回来确认（对齐不背单词"首次复习 1~2 天后、间隔超 100 天判定掌握"），答错退回第 0 阶重来，走完 7 次才毕业
- **「记错了」**：蒙对 / 手滑点错可以反悔改判 —— 掌握度退回去、重新排队、进错题本，**今日题量不会因此多算一题**
- **顶部两条进度**：上面「已做」是累计作答次数（**没有上限**，改判也不回退）；下面「会了」是确认达标的数量 —— 一眼看出"刷了多少"和"真会了多少"差多少
- **错题本**：答错自动收录，并且**把例句原文一起存进记录**（AI / 导入生成的句子不在语料表里，只存 id 的话重练时会查不出原文）
- **错题重练**：答对自动移出；半对既不进错题本、也不移出
- **AI 专练**：围绕你掌握度低的词现场生成练习句
- **AI 点评**：答完之后告诉你译文哪里别扭、该怎么改
- **对话陪练**：用已学词汇跟 AI 英文聊天

### 语音

- **整句朗读**：系统原生 TTS（**离线可用**）→ 在线整句 → 逐词降级
- **单词点读**：有道词典发音，更准（需联网，失败兜底原生）
- **状态自检**：设置 → 语音里有「系统语音状态」与重新检测，一次抖动不会让整场朗读一路降级

### AI（可选）

| 服务商 | 对话 | 语音 | 文生图 |
|---|---|---|---|
| OpenAI | ✅ | ✅ | ✅ |
| DeepSeek | ✅ | ❌ | ❌ |
| Kimi (Moonshot) | ✅ | ❌ | ❌ |
| 通义千问 | ✅ | ❌ | ❌ |
| 自定义（OpenAI 兼容） | ✅ | 可选 | 可选 |

「文生图」指说一句话让 AI 画一张新图，走的是 OpenAI 的 `/images/generations` 接口。Kimi、通义的多模态是**读图**（把图片塞进去让它描述、找 bug），不是生成图，两者不是同一件事 —— 网页版里能画图，不代表它的开放 API 也能出图。不能出图时会回退到「AI 描述颜色 + 本地渐变」，功能不受影响。想换别的画图模型，选「自定义（OpenAI 兼容）」，填一个支持出图的中转地址并勾选「支持出图」即可。

- 密钥**只存本机**，源码里零硬编码
- 设置页有**测试连接**：先本地格式校验，再发一条 `max_tokens=8` 的真实请求
- 没配 AI？功能整块置灰并说明原因，主流程一行不变
- AI 结果本地缓存 **7 天**，离线可回看，且和你的学习进度完全隔离

### 外观

- **毛玻璃**：背景钉在视口不动，窗体半透明磨砂
- **7 种主题色** + **6 款背景预设** + 相册自定义背景图
- **深色模式**：可手动，也可跟随系统
- **中 / 英双语**界面一键切换（字典的 key 就是中文原文，所以永远不会出现"模板改了忘补译文"）
- **进度条配色**：顶部两条可以走**同色系**（浅色 + 主题色），也可以**分开**（主题色 + 绿色）—— 设置里一个开关切换，旁边就是实时预览
- **首页自定义**：8 个模块拖拽排序、收纳、加回，AI 造的卡也能一起排
- **首次进入引导**：遮罩挖洞高亮真实控件，讲清搜索框 / 开始练习 / 编辑首页 / 底部导航；设置里随时「重看」
- **答题音效**：答对 / 半对 / 答错各一声，纯合成波形（无版权、离线可响），可在设置里关闭与试听

### 数据

- **打卡走势**：把每日练习量折成股票式分时图 —— 基点 100，背了涨、没背跌，**红涨绿跌**（A 股习惯）
- **连续天数**、**打卡周历**、**每日目标**（按词书独立存储）
- **目标数的是"学会了多少"**：蒙对不算 —— 只有确认通过的才 +1，反悔改判会 -1
- **跨天巩固队列**：每个词自带 `st`（已巩固几次）与 `due`（下次哪天回来），到期的会被排进下一组练习 —— 最多占一半，不挤掉新词的位置
- **掌握度概览**：已学 / 已掌握 / 全书进度（**整卡可点**，直接进词库详情）
- **本地账号**：SQLite + PBKDF2（可升级 argon2id）、UUID 主键、**软删除**、口令只留单向哈希，**零网络请求**

### 数据备份（换手机迁移）

纯本地 App 最大的代价是"换手机就全没了"，所以设置 → **数据与账号**里有一键导出 / 导入：

| | |
|---|---|
| **一键导出** | 学习进度、词书、错题、设置与 **AI 配置**打包成一个 `awword-backup-2026-10-10.json`，**内容整体加密** —— 文件里不会出现明文密钥 |
| **加密码导出** | 可选再套一层用户自设的密码（PBKDF2-HMAC-SHA256 12 万次派生）。**没有找回途径**（没有服务器可以找回），所以弹窗里会写清楚 |
| **传到另一台手机** | 导出后直接调起**系统分享面板** —— Android 分享面板里自带附近分享 / Quick Share，以及小米互传、华为分享、OPPO / vivo 互传（四家已互通，Wi-Fi 直连），选它就能无线直传，不用我们自己发明传输协议 |
| **导入前先看摘要** | 先用信封里的**明文摘要**告诉你这份备份里有几个词的掌握度、几条错题、几天记录、有没有 AI 配置，确认后才解密；**覆盖**二字写在按钮上，不藏在说明里 |
| **坏文件挡得住** | 密码不对、文件被改过、版本更新、不是本应用的备份 —— 各有各的人话提示，不会写一半进 storage |

加密是**零依赖**的：PBKDF2 派生 + HMAC-SHA256 密钥流 XOR + 完整性 MAC，复用项目里已有的 `hash.ts` / `random.ts`，没有引入任何三方库。

### 性能

- 首次启动延迟探测 CPU 算力 + 光栅化面积，自动推荐画质档位
- 四档画质 + 毛玻璃 / 动效 / 阴影三个独立细调
- **bg-flat**：背景是平滑渐变时把卡片模糊全关（渐变本身就是低频信号，模糊了肉眼也没差别）
- **分包加载**：主包只留 5 页，15 页放进 `pkgStudy` / `pkgManage` 两个分包
- 出题链路 **3 路并发**、写盘 **800ms 节流**、请求 **inflight 去重 + 熔断**

## 68 个自动化校验

每个功能改动都配一个 `_tools/check-*.js`，全部只读源码、不改工程：

```bash
cd _tools && for f in check-*.js; do node "$f" || echo "FAIL: $f"; done
```

覆盖范围包含几条"不太常见但很有用"的防线：

| 校验 | 盯着什么 |
|---|---|
| `check-exports.js` | 全项目 **262 处具名导入**是否都真实导出 —— 这类错误在 App 端会直接**白屏**且编译期不报错 |
| `check-app-compat.js` | 禁 `\p{...}` Unicode 属性转义等老引擎不认的语法，并**交叉验证编译产物** |
| `check-perf.js` | 画质档位表自洽、毛玻璃半径不许写死（必须走 CSS 变量） |
| `check-tabbar.js` | 除逻辑外还盯**可见性**（光逻辑对、渲染不出来也会全绿，吃过这个亏） |
| `check-i18n.js` | 扫裸拼接文案：拼接出来的 `复习 14 道错题` 在英文下语序是错的，必须整句进字典 |
| `check-onboarding.js` | 引导目标的选择器必须真实存在，否则改个类名就让引导静默失效 |
| `check-backup.js` | 备份**加密往返**、错密码 / 被篡改 / 版本不认识都要被挡下、密文里搜不到明文密钥、导入前摘要正确 |
| `check-native-assets.js` | APK 图标与启动图的**配置层级** —— 写错层级 HBuilderX 不报错，云打包静默回退成默认图标 |

## 技术栈

- **uni-app + Vue 3**：33 个页面与组件全部**选项式 API**，风格统一
- **TypeScript**：领域层（账号 / 哈希 / 存储 / 加密）用 TS，页面保持 JS —— Vite 内置 esbuild 剥类型，无需额外依赖
- **SQLite**：`plus.sqlite`，不可用时自动降级到 KV，两套实现接口完全一致
- **真正的零依赖**：仓库里没有 `package.json`，也没有 `node_modules` —— 校验脚本用原生 Node 跑，App 不需要安装任何三方库

## 常见问题

<details>
<summary><b>不联网真的能用吗？</b></summary>

能。题库、例句、判分、进度、打卡全部在本地。
AI 释义、AI 点评、云端语音是需要联网的**增强项**，没配就自动走本地链路，功能不缺、入口只是置灰。

</details>

<details>
<summary><b>我的学习数据会被传到服务器上吗？</b></summary>

不会。App 全程不发任何网络请求 —— 除非你自己在设置里配了 AI 服务。
账号体系是**纯本地**的：口令只存单向哈希，会话 token 走系统安全存储（Android KeyStore / iOS Keychain）。

</details>

<details>
<summary><b>App 端 `\p{L}` 这种正则为什么不能用？</b></summary>

App 端的 `app-service.js` 跑在 uni-app 自带的 JS 引擎里，不是系统 WebView，
老版本不认 Unicode 属性转义 —— 模块解析阶段直接 SyntaxError，表现是**整个 App 白屏**，
而且**编译期完全不报错**。这也是我们专门写了 `check-app-compat.js` 的原因。

</details>

<details>
<summary><b>换手机了，数据怎么搬过去？</b></summary>

设置 → 数据与账号 → **导出数据**，会生成一个加密的 `.json` 备份并调起系统分享面板。
在分享面板里选**附近分享 / Quick Share / 互传**（各家手机自带的互传已互通，走 Wi-Fi 直连），
另一台手机收到后在同一个位置**导入**即可 —— 全程离线，不经任何服务器（我们也没有服务器）。

也可以存下来手动传（微信发给自己、拷到电脑再回来都行）。备份默认不含明文密钥；
如果选了「加密码导出」，导入时还要输入同一个密码，**这个密码没有任何找回途径**。

</details>

<details>
<summary><b>能两台手机直接同步吗（不用手动导来导去）？</b></summary>

不能，而且这是有意的：这是个**纯离线** App，没有账号、没有服务器，
所以"自动同步"在架构上不存在 —— 换了手机要自己搬一次。

但搬的过程很轻：导出 → 系统分享 → 另一台手机导入，全程几十秒，
而且是**无线直传**（附近分享走 Wi-Fi 直连，不用数据线，也不经过第三方服务器）。

</details>

<details>
<summary><b>为什么要单独放一个 <code>_tools/</code> 目录？</b></summary>

因为 uni-app 跨端项目里很多坑只有真机跑起来才暴露，而每次手动逐步验证太贵。
`_tools/` 是纯 Node 脚本，只读源码做静态断言，另有一部分会做真运行时模拟
（mock 掉 storage 后跑真实状态机）。改完工程跑一遍全量，几秒内就能知道
有没有碰坏既有契约。

</details>
